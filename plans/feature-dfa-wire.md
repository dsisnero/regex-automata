## Dense wire contract and representation notes

Rust `src/dfa/dense.rs::{from_bytes,from_bytes_unchecked,write_to}` maps to
Crystal `src/regex/automata/dense_wire.cr`. The native v2 label, endian marker,
version, unused word, three semantic flag bits, transition/start/match tables,
special ranges, accelerator words, and quit-byte bitsets follow the pin.
The former Crystal `CRDFA001` payload is superseded. Like Rust, decoding accepts
native endian only, verifies alignment after initial padding, and reports the
consumed prefix even if trailing bytes follow. `to_bytes_*` returns
`{bytes, alignment_padding}`; `write_to_*` returns the byte count.

- **Owned decode:** Rust borrows aligned `u32` slices from the input. Crystal
  retains owned `Array(StateID)` storage plus its existing materialized
  `DFA::State` graph, since its APIs expose these mutable objects and it has no
  borrow lifetime parameter. Copying and materialization are proportional to
  input size and occur at construction. Searches use the existing flat table;
  there is no additional per-byte branch or lookup. `from_bytes_unchecked`
  deliberately uses the safe owned decoder, so it also validates in linear
  time rather than promising Rust's unsafe constant-time view.
- **Unused storage:** Rust ignores stride padding during validation but keeps
  its arbitrary u32 bits when writing again. Crystal stores nonzero unused
  words separately as UInt32 values, keeping them outside checked StateIDs.
  Accelerator padding and unused accelerator records are also retained in
  owned raw storage. These extra objects are construction/serialization-only;
  search still reads only the existing transition and accelerator tables.
- **Quit-byte decoding at this pin:** Rust
  `src/util/alphabet.rs::ByteSet::from_bytes` reads both u128 buckets from the
  same low-bucket slice. The native Crystal decoder deliberately does the
  same, including the resulting look-behind quit behavior. The standalone
  Crystal ByteSet helper is a portable literal-byte decoder; native decoding
  normalizes its input explicitly to preserve the pinned Rust result. Rust's
  own decode/re-encode changes the high bucket of the generated fixtures.
  Tests and the oracle check that result rather than asserting a raw byte copy.
- **Clone semantics:** Rust `DFA::to_owned` copies tables without deserializing
  them. Crystal `dfa.cr::DFA#to_owned` now does likewise; sparse conversion's
  existing dense-backed implementation uses that clone instead of a wire
  round trip. Starts, match slices, quit bytes, accelerators and transitions
  are independent; the immutable prefilter strategy reference is shared.
  Native readers still omit prefilters, as Rust does.

These are representation/ownership differences, not speed claims. Controlled
allocation and construction-cost measurements remain phase 8 work. The sparse
wrapper still has its old Crystal envelope and dense backing until phase 5b;
no sparse native wire compatibility is claimed by phase 5a.

## Reproduce the dense evidence

```bash
# Crystal fixtures, fuzz payloads, malformed boundaries, ownership/options:
crystal spec spec/dfa_native_wire_spec.cr spec/dfa_dense_spec.cr \
  spec/dfa_sparse_spec.cr spec/dfa_transform_spec.cr
# All 24 non-expensive groups, with Rust's DFA exclusions and supported paths:
crystal spec spec/dfa_vendor_suite_spec.cr -- --example 'serialization:'
# Nine Crystal outputs consumed and re-encoded by the pinned Rust crate:
scripts/check_dense_wire.sh
# Upstream unit, generated-byte, fuzz, and full serialization cases (offline):
CARGO_TARGET_DIR="$PWD/temp/rust-target" cargo test --offline \
  --manifest-path vendor/regex/regex-automata/Cargo.toml --lib dfa::dense::tests
CARGO_TARGET_DIR="$PWD/temp/rust-target" cargo test --offline \
  --manifest-path vendor/regex/regex-automata/Cargo.toml --test integration gen::dense
CARGO_TARGET_DIR="$PWD/temp/rust-target" cargo test --offline \
  --manifest-path vendor/regex/regex-automata/Cargo.toml --test integration fuzz::dense
CARGO_TARGET_DIR="$PWD/temp/rust-target" cargo test --offline \
  --manifest-path vendor/regex/regex-automata/Cargo.toml --test integration \
  dfa::suite::serialization_unminimized_default
```

Dense serialization mode applies the pinned `expensive` substring blacklist,
unsupported `leftmost-longest` exclusion, and Unicode-word-boundary/non-ASCII
haystack exclusion. `serialization:` runs is_match, non-overlapping/earliest
find, overlapping find and pattern-set checks as supported by each case;
DFA engines do not expose capture groups. The generated fixture assertions
are the nine exact spans and Unicode quit assertion in
`tests/gen/dense/mod.rs`; both `tests/fuzz/dense.rs` files are used with their
original haystack-length split and Rust preamble, never rebuilt Crystal DFAs.
